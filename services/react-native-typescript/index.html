Why TypeScript, and why me

React Native lets one codebase run on iPhone and Android. TypeScript makes that codebase safer: the editor catches mistakes in data, props and navigation before they ever reach a phone.

  • Typed end to end. API models, navigation parameters and app state are all typed, with strict mode on.
  • Native where it counts. When a feature needs iOS APIs that React Native doesn’t cover, I write the native module in Swift.
  • Shared with your web app. Types and business logic can be shared with a React and TypeScript web app.
  • Ready for both stores. Builds, signing and submissions for the App Store and Google Play.
// One typed component, running on iOS and Android
type Ride = {
  id: string;
  driver: string;
  seats: number;
};

type RideRowProps = {
  ride: Ride;
  onRequest: (id: Ride["id"]) => void;
};

export function RideRow({ ride, onRequest }: RideRowProps) {
  return (
    <Pressable onPress={() => onRequest(ride.id)}>
      <Text>{ride.driver}</Text>
      <Text>{ride.seats} seats</Text>
    </Pressable>
  );
}

Is React Native right for your app?

React Native is a great fit when

  • You need iOS and Android at launch with one team
  • Your team already knows React and TypeScript
  • Most of the app is screens, lists, forms and API calls

Native Swift is the better call when

  • The app relies on heavy graphics, AR or advanced camera work
  • It depends on the newest Apple-only features
  • Smooth, platform-perfect animation is the product itself
