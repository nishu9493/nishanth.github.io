How I build websites that are fast and easy to find

The principles I follow for websites and web apps, from page speed and search to accessibility and working with your mobile app.

Nishanth Kumar 26 November 2026 3 min read

Most of my work starts on the iPhone, but almost every app needs a website: a page that explains the product, a dashboard for customers, or an admin panel for the team. I build those in React and TypeScript, with PHP and MySQL backends, as I did for the Innovation Factors analytics platform and the Business Dhronacharya course platform. These are the principles I follow.

Start with what the site is for

A marketing site, a web app and an admin panel are very different things. Before choosing any technology, I want to know who visits, what they should be able to do, and what counts as success: sign-ups, bookings, sales or saved time. That decides the structure, the content and the stack.

Fast by default

Speed is a feature. Visitors leave slow pages, and search engines notice. I keep pages light, serve images at the size they’re shown, avoid libraries the site doesn’t need, and check every page with tools like Lighthouse and PageSpeed Insights before it goes live.

Easy to find on Google

Good search results start with good structure, not tricks:

  • One clear main heading per page, and a sensible heading order below it.
  • A unique title and description for every page.
  • Structured data, so search engines understand what a page is about.
  • A sitemap, submitted through Google Search Console.
  • Content that answers the questions your customers actually search for.

Accessible to everyone

An accessible site works for more people and is usually better built. I use semantic HTML, make sure everything works with a keyboard and a screen reader, keep text readable with enough contrast, and give images meaningful alternative text.

Built to work with your app

When there’s also a mobile app, the website shouldn’t be a separate world. I build both on the same API, data and sign-in, so a change in one shows up in the other. Admin panels let your team manage users, content and orders without touching code.

Choosing the stack

For a marketing site, a fast static site is often all you need. For a web app or dashboard, I use React with TypeScript. For the backend, PHP and MySQL with REST APIs have served many of my projects well, with AWS or Firebase for hosting, storage and sign-in. The right choice depends on your team and where the product is heading, so I’ll explain the trade-offs rather than pick by habit.

The result

A site that loads quickly, shows up in search, works for everyone and fits with the rest of your product. If you’re planning one, I’m happy to talk it through.
